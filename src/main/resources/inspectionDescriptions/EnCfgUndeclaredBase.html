Reports a config class whose base class is not declared before it, where Addon Builder would look for it.

class MyApple: Apple {} inside CfgVehicles needs a class Apple (usually the external declaration class Apple;) earlier in the same file. The IDE resolves Apple through every indexed config, so navigation works and nothing looks wrong; binarising then fails with Undefined base class 'Apple', because CfgConvert reads one config.cpp at a time.

The lookup is CfgConvert's, each rule checked by binarising a test config:

  • a class of that name declared before the derived class in the same body; one declared after it is not seen;
  • else the same in each enclosing body, before the enclosing class, up to the top of the file; a sibling section such as CfgWeapons is never searched;
  • else a class inherited by an enclosing class from its base. That is what makes class DamageSystem: DamageSystem work inside class MyApple: Apple when Apple declares one, and fail when Apple is only class Apple;;
  • names ignore case.

Add 'class Apple;' inserts the external declaration at the top of the section, after the ones already there. Applied to the whole file, it adds every missing one at once.

Only config.cpp is checked, and only a base that some indexed config declares: one found nowhere may belong to a dependency outside the roots.
