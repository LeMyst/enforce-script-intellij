Reports a type, function, field or method that is declared only in a later script module than the file using it, such as PlayerBase (4_World) named from a 3_Game file.

DayZ compiles scripts in five modules, in order: 1_Core, 2_GameLib, 3_Game, 4_World, 5_Mission. Each one sees its own declarations and those of the modules before it, never those after. Such a file stops the game at start with Can't compile "Game" script module.

A file's module comes from the files[] of CfgMods → defs in the addon's config.cpp, and otherwise from the standard folder names (3_Game, ...). A file in no known module is not checked, and one visible declaration is enough: a class declared in 3_Game and modded in 4_World can be named from 3_Game, but the members that only the 4_World layer adds cannot.

A modded class is reported as well when only a later module declares its class, such as modded class PlayerBase in 3_Game. That layer does not compile, so it does not make the class visible from its own module either.
