Reports an override in a modded class whose body never calls super with the method's own name.

In a modded class, super.Method() calls the previous layer: other mods' layers and, at the end of the chain, vanilla. An override that never calls it drops all of them. The mod still compiles and works when tested alone, and breaks only next to other mods: SetActions without super.SetActions() removes every other action from the item, and OnStoreSave / OnStoreLoad without it desynchronise the persistence stream, so items fail to load after a restart.

One call anywhere in the body is enough, in any branch. Methods of an ordinary subclass are never reported: replacing a method's behaviour there is ordinary.

By default only void methods are reported, plus a few whose super call is needed whatever they return: OnStoreSave, OnStoreLoad, SetActions, EEInit, EEDelete, OnRPC, OnVariablesSynchronized and OnInit. A value-returning override is usually an intended replacement (return false;); the option reports those too.

Add super call inserts the call as the first statement. In a bool method it keeps the shape vanilla's persistence uses: if (!super.OnStoreLoad(ctx, version)) return false;. For the rare intended replacement, suppress the warning on that method.

Nothing is reported when the overridden method cannot be found, such as a base in a dependency mod that is not among the script roots.
